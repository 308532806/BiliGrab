# BiliGrab 1.9.4

一句话：**设置里的「优先 H.264」开关不会再变成一个竖长条色块了。**

---

## 修了什么

### H.264 开关的几何恢复设计值

问题出在 `NeumorphicControls.dressSwitch()`：轨道和滑块的 dp 尺寸先被算出来，
又被 `NeumorphicSurface.create()` 当成 px 再乘了一次屏幕密度。
在 3.0 密度的屏幕上，一条设计为 52×28dp 的轨道被画成了 468×252px ——
也就是设置页里那块明显不对的竖长条色块。

| | 设计值 | 缺陷版实测 | 1.9.4 实测 |
|---|---|---|---|
| 轨道尺寸 | 156×84 px（52×28dp） | 468×252 px | 154×81 px |
| 滑块 | 66×66 px 正圆 | 66×84 px 竖椭圆 | 66×66 px 正圆 |

修复做了四件事：

1. dp 换算结果只在 dp 语义正确的地方使用（`setSwitchMinWidth` 仍收 px）；
2. 轨道/滑块尺寸统一走 `Math.round(dp(...))` 的 dp 值，消除双重缩放；
3. 滑块包一层 `LayerDrawable` 加垂直 `setLayerInset`，抵消 AOSP `Switch.onDraw`
   把滑块 bounds 纵向拉满整个控件高度的行为；
4. 轨道包一层 `LayerDrawable` 加左右 `setPadding`，恢复设计里 4dp 的端部留白。

**真机验证（OPPO PDPM00 / Android 12 / density 3.0）：**

- 逐像素扫描：轨道 154×81px（设计 156×84px，差值为圆角抗锯齿边缘，符合预期）；
- ON / OFF 两态均为正圆滑块 + 药丸形轨道；
- 设置落盘复测：关闭 → 重启应用 → 仍为关闭状态。

## ⚠️ 签名说明（重要）

本项目的签名密钥在 1.9.2 发布时曾被意外更换，导致：

| 版本 | 签名证书 SHA-256 前缀 |
|---|---|
| 1.9.0 / 1.9.1 | `5F:71:50:AA…`（原始密钥） |
| 1.9.2 / 1.9.3 | `2D:F9:DF:23…`（意外生成的新密钥） |
| **1.9.4** | `5F:71:50:AA…`（回归原始密钥） |

- 从 **1.9.1 或更早**升级：直接覆盖安装即可；
- 从 **1.9.2 / 1.9.3** 升级：需要先卸载一次（签名不匹配，系统会拒绝覆盖安装；
  卸载会导致应用内设置重置，已下载到公共目录的文件不受影响）；
- CI 的签名配置已修正回原始密钥，后续版本不会再出现这个问题。
