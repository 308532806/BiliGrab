# BiliGrab v1.9.0

## 修复：玻璃态下「深海蓝」标签变成白色

设置里选玻璃态，主题色的「深海蓝」按钮会渲染成一个白块。

根因在 `NeumorphicDrawable.drawGlass()`：它从头到尾**只画了 `glassTint`**
（`#5CFFFFFF`，36% 的白雾），**没有任何一处引用 `baseColor`** —— 也就是
`colors()` 设进去的底色在玻璃态下是个**静默空操作**。新拟态走的是实心填色
路径，所以一直看不出问题；一换玻璃态就露馅。

它能潜伏这么久，是因为只在那几套"底色换了之后字色也得跟着换"的主题色上才明显。
深海蓝恰好是五套里**唯一**白色字比黑色字对比度更高的（白 7.48:1 / 黑 2.52:1），
所以最先被看到 —— 其余四套即使面被冲淡，黑字仍然勉强能读。

修法是给主色面单开一条路径，而不是让色卡去将就白雾：色卡存在的意义就是准确显示颜色。

| 方法 | 作用 |
|---|---|
| `accent(color, light, dark)` | 分派器：玻璃态走主色路径，新拟态走填色路径 |
| `faceColor()` | 返回「这个面实际呈现的颜色」，供在面上摆文字时算对比度 |

主色面先平铺主色，然后**跳过那层白雾**；方向光和渐变描边照旧 —— 所以它仍然有玻璃的
明暗，只是没有把颜色冲淡的那层白。

## 顺带修掉的三个同源缺陷

**1. 玻璃态下所有色卡看不出选中状态。** `applyChipStates` 和 `paintConnChip` 里
各有一句 `glass(true)`，把每个芯片都画成凸起 —— on/off 完全一样。现在无论哪个引擎
都是「选中凸起、未选中凹入」，玻璃态的凹陷靠方向光表达，仍然读得出来。

**2. 下载管理页的空状态图标一直是樱花粉。** 布局里标了 `neu:accent`，但这个
Activity **从没调用过 `applyAccentTags`**，tag 是死的。实机上就是粉色的下载图标
配着一整套蓝色界面。这类"漏一行 Java"的缺陷不会报错 —— tag 在那里、函数也在那里，
只是没连上，只能靠实机换主题色截图发现。

**3. 色卡未选中时的字色配错。** 凹陷面会被内阴影压暗（实测逐通道系数
樱花粉 0.861 / 默认蓝 0.852 / 薄荷绿 0.836 / 薰衣草紫 0.797），但字色是按本色算的。
结果默认蓝配了黑字，落在真实的凹面 `#0068D9` 上只有 **3.58:1**（白字有 5.88:1）；
薰衣草紫同理（黑 3.81 / 白 5.19）。修好之后五张卡最差 5.11:1。

## 按 impeccable 规范统一按钮、布局与配色

装了 [impeccable](https://github.com/pbakaus/impeccable) 这套前端设计规范，按它逐条过了一遍。

**按钮角色不再写死颜色。** 新增 `neuRole` 属性（`filled` / `tonal` / `outlined`），
由 `NeuButton` 在运行时解析。`styles.xml` 里那三处写死的 `@color/scheme_0_primary`
因此删掉 —— 那也是编译期快照，换主题色不会跟着走。

**主色上的文字改为按面色现算**，而不是各写各的：

| 函数 | 用在哪 | 阈值 |
|---|---|---|
| `contrastOn(bg)` | 通用，黑白二选一 | 取对比度更高者 |
| `primaryText(ctx)` | 主色面上的文字 | 4.5:1 |
| `primaryIcon(ctx)` | 主色面上的图标 | 3:1 |

分两档是因为图标按规范只需 3:1，正文要 4.5:1。浅色页面上樱花粉的实测效果：
`#FB7299` 原本只有 **2.39:1**，逐档混到 `#AE526C` 才够 4.50:1。
深海蓝本来就够（6.80），不动。

**三个文字令牌调深**，原来那两级落在 4.5:1 上下 —— 属于"看着能读、但不过线"：

| 令牌 | 浅色 | 深色 |
|---|---|---|
| 次要文字 | `#696C78` → `#505360`（6.94:1） | 不变 |
| 三级文字 | `#888899` → `#6A6D7B`（4.67:1） | `#808080` → `#8E8E93`（5.28:1） |

**补上系统自带、但会露出来的表面。** 这些是"没自己画、换主题色后才发现不搭"的部分：

- 滚动条滑块改成圆头细条并按色板走（系统默认是直角灰条，和整套圆角浮雕不搭）；
- 列表滚到尽头的边缘光晕、列表分隔线一并按色板指认；
- 输入框光标按主题色走 —— 原先注释说"平台改不了"是错的，
  `setTextCursorDrawable` 从 API 29 起可以直接给 Drawable（本机 Android 12）；
- 去掉 `activity_downloads.xml` 上残留的 `?selectableItemBackground`。
  主题里已经把它压成 `@null`，所以行为无变化，只是不再和「无涟漪」规则冲突。

## 验证

OPPO Reno4 / Android 12，**root 安装**，每轮都用 SHA-256 比对确认设备上跑的就是新构建的包。

| 场景 | 五张色卡最差对比度 |
|---|---|
| 玻璃态 + 深海蓝 | 5.11:1（薰衣草紫） |
| 新拟态 + 深海蓝 | 4.70:1（默认蓝） |
| 新拟态 + 深海蓝 + 深色 | 5.18:1（默认蓝） |

字体放大到 1.3 倍：无截断、无重叠。下载管理页空状态图标实测 `#1652A8`
（修复前是樱花粉）。

关于 impeccable 的检测器：它只认 `css` / `html` / `svelte` / `astro`
（用自造的 CSS 验证过它确实会报 `side-tab`），对 Android XML/Java
**完全不可见** —— 所以在本项目里它返回的 `[]` 不代表合规，是根本不适用。
craft floor 是逐条手工审的：无 emoji 充当图标、无渐变文字、无单边色条、
无零模糊硬偏移阴影；`Text.Code` 用 monospace 是版本号与错误原文的逐字对齐用途，
属于该规则明确允许的场景。

## 已知边界

- 默认主题色是樱花粉，不是 `#007AFF`。
- 切换视觉引擎或主题色会 `recreate()` 当前界面。
- 新拟态下每个控件会因为阴影外扩（`3 × elevation`）而视觉上小一圈，玻璃态外扩为 0。
- 玻璃态下**走新拟态绘制的主色面**（主题色卡、开关的开启态轨道、播放进度条的已播放段）
  **不带白雾**，比其它玻璃面略"不玻璃"。这是为了让颜色样本准确而做的取舍。
  下载列表里的进度条不走这套绘制（它用框架的 `setProgressTintList`），
  所以本来就是准确的主色，不受影响。
- 同时只能跑一个下载任务。
- 8 条并发连接实测比 4 条慢（27.39 vs 35.50 Mbps），默认 4。
