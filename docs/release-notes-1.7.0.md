## v1.7.0

修掉两个用户报的问题，并补上自选下载目录与独立的下载管理页。

### 进度条不动（找到根因了）

之前只把 `Content-Length` 当总量。经代理取 googlevideo 时响应是 chunked、
不带这个头，于是总量算成 0，百分比死锁在分档基准值上 —— 而 VPN 里明明
看得到流量。这就是「有速度但进度条不动」的成因。

现在按可信度依次取总量：`Content-Range` 总长 → `Content-Length`
（206 时补上起始偏移）→ 解析阶段拿到的接口体积。进度全部来自真实写入字节数。

### 自定义下载目录

设置页新增「下载位置」，可任选一个目录，B 站与 YouTube 共用。

默认仍是视频进 `Movies/BiliGrab`、音频进 `Music/BiliGrab`（这样相册和音乐
播放器能直接扫到）；选了自选目录就统一放进去。

### 下载管理页（首页右上角）

实时进度条、真实速度（3 秒滑动窗口）、剩余时间，
以及暂停 / 继续 / 取消 / 重试 / 删除 / 清除已完成。

- 每条任务独立工作目录，带签名校验 —— 换了画质续传会拼出坏文件，
  所以签名不一致就重下。
- 暂停与取消在每写满一个数据块之后才检查，半成品始终可续传。
- 删除选「只删记录」或「连文件一起删」；正在下载时先停稳再删，
  否则后台线程会把碎片重新写出来。
- 取消保留记录（之后能重试），残留文件清掉。
- 合成阶段也能被打断（此前点了暂停还会一路跑完）。

### 五个只在真机上才暴露的缺陷

- **`MediaMuxer.stop()` 会对已经写好的文件报错。** OPPO 的
  `OplusMPEG4Writer` 抛 `-1007`，但产物 `moov` 完整、轨数与样本数正确、
  播放器能播 —— 文件是好的，是 `stop()` 在撒谎。改为在收尾之后自己
  解析 MP4 结构验收。
- **撞名时把 SQLite 报错直接弹给用户**（`UNIQUE constraint failed`）。
  改为自动加序号，如 `视频 (2).mp4`。
- **单 P 视频文件名变成「标题 - 标题」。**
- **合成失败的提示认错了画质**，480P 会显示成「未知画质 画质」。
- **界面上两处自相矛盾**：删除正在下载的任务时弹窗说「已经下载完成」；
  取消确认框两个按钮都叫「取消」（一个执行、一个关闭）。

### 安装

```
adb install -r BiliGrab-1.7.0.apk
```

OPPO / 一加等 ColorOS 机型请在 root 下安装，否则会被系统拦截：

```
adb push BiliGrab-1.7.0.apk /data/local/tmp/bg.apk
adb shell "su -c 'pm install -r /data/local/tmp/bg.apk'"
```

`pm install -r` 会清掉应用设置（下载目录、画质偏好、代理），下载记录
和已完成文件不受影响。

### 已知限制

- **4K / 8K / 真彩仍不可用。** 这几档由账号权限决定，B 站未登录账号
  拿不到地址 —— 不是客户端能绕的。
- **YouTube 需要代理**，且出口 IP 的信誉会影响解析结果。
- 同时只跑一条下载（单线程队列，共用一条前台通知）。
- 主题色默认是樱花粉 `#FB7299`，不是系统蓝。
